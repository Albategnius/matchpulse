# MATCHPULSE

**Beyond the scoreline — explain why the game changed.**

MATCHPULSE is an evidence-first match intelligence system. It detects meaningful changes in football patterns from an event stream, verifies the supporting events, and turns the same validated insight into three different experiences: a fan story, an analyst breakdown, and broadcast-ready narration with a machine-readable overlay payload — in English and Bahasa Indonesia.

> **All data is synthetic.** Teams (Northbridge Athletic, Harbour City Rovers), players (`H07`, `A10`) and events are generated by this project. Nothing here is official Premier League data or depicts real matches, clubs or people.

Built for the Microsoft × Premier League *Inside the Game* Developer Hackathon 2026.

**Live demo (Azure Container Apps):** https://matchpulse.politefield-ec1b9bf6.southeastasia.azurecontainerapps.io  ·  health: https://matchpulse.politefield-ec1b9bf6.southeastasia.azurecontainerapps.io/api/health  ·  no login or key required.

## The problem

Match statistics say *what* happened — 18 shots, 54% possession — but not *why the match changed*, *which evidence supports that explanation*, or *how a casual fan, an analyst and a broadcaster should each hear about the same moment*. Generative AI can write fluent match reports, but it also invents numbers and confidently claims causes the data cannot support.

## The solution: Evidence-to-Story Intelligence

```
synthetic events / CSV → validation → deterministic analytics → match-shift detection
   → evidence registry → 4-agent workflow (Microsoft Agent Framework) → reviewed narratives
   → dashboard, broadcast overlay JSON, exports, evaluation
```

1. **Synthetic Match Lab** — six reproducible scenarios (sustained dominance, high press, counterattacking, momentum swing, late comeback, low-event match) with **ground-truth annotations** of the windows where each pattern was injected. Same seed → identical match.
2. **Deterministic analytics** — shots, passes, progressive actions, final-third entries, pressures, press-linked turnovers, fast breaks, possession time, rolling windows and match-state transitions. Every formula is in [`docs/METRICS.md`](docs/METRICS.md). No xG, speeds or tracking metrics — the data does not support them.
3. **Explainable match-shift detection** — each detected moment has a time window, team, before/after metric deltas against a stated baseline, an evidence-strength score, limitations, and the next analytical question. Wording is associative ("coincided with", "consistent with"), never causal.
4. **Multi-agent workflow on Microsoft Agent Framework** — Event Analytics Agent → Tactical Insight Agent → Narrative & Personalization Agent ⇄ Evidence & Quality Reviewer, with typed messages, a bounded regeneration loop, timeouts and a full execution trace. See [`docs/AGENTS.md`](docs/AGENTS.md).
5. **Microsoft Foundry (optional)** — when configured, the Narrative agent uses a Foundry model (via `FoundryChatClient`, Entra ID / managed identity, no API keys) to reword verified claims for each audience. The model **cannot add claims or change their evidence**, and every number it writes is checked by the reviewer. Without Foundry the app runs fully on deterministic templates.
6. **Evidence & Quality Reviewer** — checks every number in every sentence against the evidence registry, removes unsupported or causal claims, requests one regeneration, and otherwise falls back to the verified template. A *simulated faulty model* mode in the UI shows this happening.

## Measured results

From `python scripts/evaluate.py` (full report: [`reports/EVALUATION.md`](reports/EVALUATION.md)). Thresholds were tuned on dev seeds 0–9; these results are on **held-out seeds 100–129 (180 matches)**.

| | Precision | Recall | F1 |
|---|---|---|---|
| Match-shift detection, all patterns | 0.82 | 0.87 | 0.84 |
| Weakest pattern (counterattack) | 0.67 | 0.60 | 0.63 |

- Template narratives: 100% of 1,292 claims verified against evidence (180 narratives, 3 modes × 2 languages).
- Reviewer stress test: 215 of 215 corrupted claims removed, 0 false alarms — against a *simple* fault model (changed numbers, explicit causal words). Subtler, number-free errors are not caught by this checker.
- End-to-end workflow (local mode): p50 ≈ 0.13 s, 0% failures over 30 runs.

## Microsoft technologies

| Technology | Role in MATCHPULSE |
|---|---|
| **Microsoft Agent Framework** (`agent-framework-core`) | `WorkflowBuilder` graph of four `Executor` agents with typed handoffs, a reviewer → narrative regeneration edge, and workflow events captured as the execution trace. |
| **Microsoft Foundry** (`agent-framework-foundry`) | `FoundryChatClient` powers the Narrative & Personalization `Agent` for audience/language rewording, authenticated with `DefaultAzureCredential`. |
| **Azure Container Apps** | Hosts the FastAPI service and dashboard; `infra/deploy-azure.sh` builds the image in Azure and wires a system-assigned managed identity to Foundry. |
| **GitHub** | Source control, reproducible evaluation and documentation. |

## Run it locally (no keys needed)

Requires Python 3.11+ (tested on 3.13).

```bash
git clone https://github.com/Albategnius/matchpulse && cd matchpulse
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install --pre -r requirements-dev.txt
uvicorn matchpulse.api:app --port 8000
```

Open http://localhost:8000. The default demo (momentum swing, seed 7) runs immediately.

```bash
pytest -q                            # 45 tests
python scripts/evaluate.py           # regenerates reports/evaluation.json and EVALUATION.md
python scripts/generate_samples.py   # regenerates data/samples/*.csv|json
```

### Enable Microsoft Foundry (optional)

Copy `.env.example`, set `FOUNDRY_PROJECT_ENDPOINT` and `FOUNDRY_MODEL`, run `az login`, then start the app. `/api/health` reports which writer is active. Details: [`docs/DEPLOY_AZURE.md`](docs/DEPLOY_AZURE.md).

## Deploy to Azure

The script asks for confirmation before creating billable resources and only reports success after `/api/health` responds on the public URL. Step-by-step guide: [`docs/DEPLOY_AZURE.md`](docs/DEPLOY_AZURE.md).

## Honest limitations

- Detection is evaluated on synthetic ground truth from the same generator family; real-world accuracy is not claimed.
- "Press-linked" turnovers are a time-and-distance association, not proof that pressing caused them.
- Live Foundry narrative quality has not been benchmarked in this repository's evaluation.
